# Cypress-тесты для FS21-diplom («ИдёмВКино»)

Автотесты для приложения бронирования билетов в кино:
тестируемый репозиторий — https://github.com/Evgeniy-Varlamov/FS21-diplom,
живой стенд — http://qamid.tmweb.ru (админка: http://qamid.tmweb.ru/admin,
логин `qamid@qamid.ru` / пароль `qamid`).

## Установка

```bash
npm install
```

## Запуск

```bash
npm run cy:open   # интерактивный режим (Test Runner)
npm run cy:run     # headless-прогон всех спеков
npm run test:home
npm run test:admin-login
npm run test:booking
```

## Структура проекта

```
cypress/
  e2e/
    home.cy.js          — проверка корректности отображения главной страницы
    admin-login.cy.js   — логин в админку (happy + sad path из фикстуры users.json)
    booking.cy.js        — бронирование билета в зал, полученный из админки
  fixtures/
    selectors.json      — ВСЕ локаторы проекта (см. п.5 задания)
    users.json           — тестовые данные для логина (happy/sad path)
  support/
    commands.js          — кастомные команды (cy.getBySel, cy.adminLogin, cy.assertNoPhpErrors, cy.normalizeHallName)
    e2e.js
cypress.config.js
```

## Принцип хранения локаторов (рефакторинг, п.5)

Ни один спек не содержит "зашитых" CSS-селекторов напрямую — все локаторы
лежат в `cypress/fixtures/selectors.json` и читаются либо через
`cy.fixture('selectors')`, либо через кастомную команду `cy.getBySel('home.movieTitle')`.
Если верстка приложения поменяется, достаточно поправить значения в одном файле,
не трогая сами тесты.

## Важные ограничения и допущения

Приложение — учебный проект без `data-testid`/`data-cy` атрибутов, поэтому
локаторы в `selectors.json` намеренно опираются на реальные тексты интерфейса
(заголовки, плейсхолдеры, легенду) — они подтверждены скриншотами живого
приложения: главная страница, форма логина и все 5 разделов админки
(«Управление залами», «Конфигурация залов», «Конфигурация цен», «Сетка
сеансов», «Открыть продажи»). Единственный не верифицированный вживую экран —
карта зала/выбор места при бронировании. Все найденные несоответствия и
ограничения зафиксированы в **[ISSUES.md](./ISSUES.md)**.

Важная деталь архитектуры `booking.cy.js`: в админке нет таблицы залов со
статусом "доступен" — реальный признак доступности зала для брони — статус
продаж в разделе "Открыть продажи" (`Продажа билетов открыта!!!`). Именно его
и вычитывает `cy.findAvailableHallFromAdmin()`.

Тест бронирования **присутствует в проекте**, как того требует задание, даже
если шаги выбора места потребуют донастройки локаторов после первого прогона
на реальном стенде — см. ISSUES.md, пункт №4.

## Что делать, если тест падает из-за селектора

1. Открыть нужную страницу приложения в браузере, открыть DevTools.
2. Найти актуальный локатор нужного элемента.
3. Поправить соответствующее значение в `cypress/fixtures/selectors.json`.
4. Спек-файл менять не нужно.
